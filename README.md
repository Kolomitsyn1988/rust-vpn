# rust-vpn

Собственный VPN-клиент и сервер на Rust: зашифрованный TCP-туннель и SOCKS5-прокси на стороне клиента.

## Как это устроено

```
Приложение ──> SOCKS5 127.0.0.1:1080 (vpn-client)
                     │  XSalsa20-Poly1305 поверх TCP
                     ▼
                 vpn-server ──> целевой сервер в интернете
```

* Каждый кадр шифруется XSalsa20-Poly1305, ключ выводится из общего секрета (PSK) через HKDF-SHA256.
* Клиент — локальный SOCKS5-прокси: каждое соединение заворачивается в отдельный туннель до сервера.
* Доменные имена резолвятся на сервере (семантика `socks5h`), поэтому DNS-запросы не утекают мимо туннеля.

## Быстрый старт

1. Сгенерируйте ключ (32 случайных байта в hex):

   ```powershell
   $bytes = New-Object byte[] 32
   [System.Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
   ($bytes | ForEach-Object { $_.ToString('x2') }) -join ''
   ```

   Или на Linux/macOS: `openssl rand -hex 32`.

2. Запустите сервер (например, на VPS):

   ```
   cargo run -p vpn-server -- --listen 0.0.0.0:51820 --psk <ключ>
   ```

3. Запустите клиент:

   ```
   cargo run -p vpn-client -- --server <ip-сервера>:51820 --psk <ключ>
   ```

4. Укажите в приложении SOCKS5-прокси `127.0.0.1:1080` (в браузерах выбирайте вариант с DNS через прокси). Проверка через curl:

   ```
   curl --socks5-hostname 127.0.0.1:1080 https://example.com
   ```

Проверить сборку и туннель целиком без внешней сети:

```
powershell -ExecutionPolicy Bypass -File scripts\smoke_test.ps1
```

## Протокол (v1)

Кадр на проводе: `[u32 LE длина][nonce 24 байта][ciphertext + tag]`.

Внутри шифрованного кадра — сообщение: `CONNECT` (адрес цели в SOCKS5-формате), `CONNECT_OK`, `CONNECT_ERR`, `DATA`, `CLOSE`.

## Структура

* `crates/vpn-core` — шифрование, фрейминг, ретрансляция (общее для клиента и сервера)
* `crates/vpn-server` — принимает туннели и дозванивается до целей
* `crates/vpn-client` — SOCKS5-прокси, отправляющий трафик в туннель

## Ограничения MVP

* Только TCP; UDP (в том числе DNS по протоколу UDP) через туннель не ходит.
* Одно прикладное соединение = одно TCP-соединение до сервера (нет мультиплексирования).
* AEAD защищает содержимое, но у кадров нет номеров/анти-реплея.
* Нет keepalive и переподключения.

## Roadmap

1. Рукопожатие с одноразовыми session-ключами и счётчиками кадров (анти-реплей).
2. Мультиплексирование нескольких потоков в одном туннеле (yamux/QUIC).
3. UDP-релей — откроет DNS и игры.
4. TUN-интерфейс (Wintun на Windows) для полносистемного VPN без настройки прокси.
5. Конфиг-файл, лимиты трафика, статистика.

## Безопасность

* Используйте ключ длиной 32 байта (см. выше) и не передавайте его по открытым каналам.
* Сервер аутентифицирует клиентов только PSK — не открывайте порт наружу без сильного ключа.
* Это учебный/MVP-проект. Для продакшена смотрите на зрелые решения: WireGuard, Amnezia, Outline.
